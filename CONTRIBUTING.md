# Как предложить изменение

SEED постоянно дополняется. Каждая правка видна в истории репозитория.

- **Содержательные изменения** — принципы, уровни, правила входа, публичные списки, **анкеты** (`registrar/questionnaires/`) и **правила проверки** (`registrar/registrar/check.py`) — принимаются **по решению Совета граждан**.
- **Технические правки** (опечатки, ссылки, формулировки без изменения смысла, исправления кода без изменения правил) — мейнтейнер и один проверяющий.
- **Идея или ошибка:** открой Issue. Не пиши в Issue ничего личного — он виден всем. Заявки через Issue не принимаются: только через бота NOWA.
- **Готовая правка:** Pull Request с описанием «что и зачем». Для кода — тесты должны проходить: `cd registrar && python3 -m unittest discover -s tests`.

## Что здесь запускается
Почти всё в SEED — тексты. Исключение — `registrar/`: открытый код регистрации (только стандартная библиотека Python, без сети). Он проверяет блоки заявок; бот NOWA работает на этом же коде. Данные людей в репозиторий не попадают никогда — база живёт на облачном сервере NOWA.

Анкеты в `templates/` и `registrar/questionnaires/` должны совпадать по полям — это проверяет тест.
